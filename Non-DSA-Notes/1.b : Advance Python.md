**1. Magic (Dunder) Methods :**  
Magic methods are special methods surrounded by double underscores. They are called magic methods because Python automatically calls them when certain operations happen. **You don't call them directly. Python runtime calls them.**
  
  ```__init__
      __str__
      __repr__
      __len__
      __eq__

      Ex : len(obj)   ----> Internally : obj.__len__()
      Ex : print(obj) ----> Internally : obj.__str__()
```

* Common Methods

| Method | Purpose |
|---------|---------|
| `__init__` | Constructor | Called when object is created.
| `__str__` | Human-readable string (`print`) |
| `__repr__` | Developer/debug representation (`repr`) |
| `__len__` | Supports `len(obj)` |
| `__eq__` | Equality (`==`) |
| `__lt__` | Less than (`<`) |
| `__add__` | Addition (`+`) |
| `__iter__` | Returns iterator |
| `__next__` | Returns next item |
| `__getitem__` | Indexing (`obj[i]`) |
| `__contains__` | Membership (`in`) |

**2. Mutable vs Immutable :**

Mutable : A mutable object can be modified after it is created. Ex : list, dict, set, bytearray.  
Immutable : An immutable object cannot be modified after creation. Ex : int, float, bool, str, tuple, frozenset, bytes

```python
  Ex : x = "hello"
  x += " world"
  print(x)    ----> output ; hello world

--> Looks like the string changed. It didn't. Python created a new string object.
```


> ### Object Identity : Use `id(obj)` to check whether an object changed or a new one was created.




Q : Why are Strings Immutable?
  - Thread-safe to share across code.
  - Can be hashed (used as dictionary keys).
  - Performance optimizations (interning/caching).
  - Prevent accidental modification.

Q : Why are Lists Mutable?
  - Because they're designed for dynamic collections where items are added, removed, or updated efficiently.


Q : Why are dictionary keys immutable?
  - Because keys are stored using their hash value. If a key changed after insertion, its hash could change, making it impossible to find the entry reliably.

Q : Is Tuple mutable ? 
  - **Tuples: Immutable Container, Mutable Contents**
  - **The tuple structure is immutable, but it can contain mutable objects whose contents can change.**
          ```
          t = ([1, 2], 3)
          t[0].append(4)
          print(t)   ---->  Output : ([1,2,4],3)
          The tuple still points to the same list; only the list's contents changed.
          ```

Q : Does += always create a new object?
  - For immutable types (int, str, tuple): Yes
  - For mutable types like list: No, it usually modifies the existing object in place.

Q : What parameter should you use instead of [] as a default value?
  - Use None, then create the mutable object inside the function.

This guarantees its hash value never changes, so Python can always find the correct memory bucket.The Dictionary (The Warehouse): Is mutable. You can add new shelves (keys) or change the items sitting on those shelves (values) at any time.Because a dictionary is mutable, its own hash value would change if it were modified. Therefore, Python blocks you from using a dictionary as a key inside another dictionary:

**Q : Does Python use pass-by-value or pass-by-reference?     
Python uses pass-by-object-reference (also called call-by-sharing). Function parameters receive a reference to the same object. If the object is mutable and modified in place, the caller sees the change. If the parameter is reassigned to a new object, only the local reference changes, and the caller is unaffected.**

```python
Function call: object reference is copied
Mutable object: Modify object → Caller sees changes
Immutable object: Modification creates new object → Caller doesn't see changes
-->  Rule to remember: Modifying an object and reassigning a variable are two completely different operations in Python.
```

### Decorators : 

A Python decorator is a design pattern that allows you to modify or extend the behavior of a function, method, or class without permanently changing its source code

### Iterators
An iterator is an object that returns one item at a time.  
Instead of loading everything into memory, it produces values on demand.  
```python
nums = [1, 2, 3]

it = iter(nums)

print(next(it))
print(next(it))
print(next(it))
```

**Q. Iterable vs Iterator :**
| Iterable           | Iterator                        |
| ------------------ | ------------------------------- |
| Can be looped over | Produces next item              |
| Has `__iter__()`   | Has `__iter__()` + `__next__()` |
| list, tuple, dict  | Result of `iter()`              |
| Holds all elements in memory at once.| Uses lazy evaluation to fetch items dynamically.
**in the above ex: nums is an iterable, it is an iterator**


**Q. How does a for loop work internally?**  
```python
for x in nums:
    print(x)

Internally, Python does approximately:
it = iter(nums)

while True:
    try:
        x = next(it)
        print(x)
    except StopIteration:
        break
```
**just understand that an iterator implements __iter__() and __next__().**  
StopIteration : When there are no more items, next(it) raises StopIteration. The for loop catches it automatically.

### Generators :
A generator is an easier way to create an iterator.
Instead of writing a class with __next__(), use **yield.**
Generators are special functions that return a lazy iterator object, allowing you to stream or calculate sequences of data on the fly instead of loading the entire dataset into memory at once. They are ideal for handling massive data files, API data streams, or infinite mathematical sequences.

> yeild : Pauses the function and remembers its state. Next call resumes from where it stopped.


|Feature      |yield (Generator)      |return (Normal Function)| 
|-------------|-----------------------|------------------------|
|Execution    |Pauses execution and saves internal state.      |Terminates the function entirely.
|Memory       |Highly efficient; allocates data item-by-item.  |Can cause memory errors with large datasets.
|Values       |Emits a continuous sequence over multiple calls.|Returns a single output or collection at once.

**Q. Why Generators?**    
  - Instead of loading 1 million records into memory: return huge_list
  - use : yield record. One record at a time. Memory efficient.

**Q. Generator Expression**    
  - Like list comprehension.
  - (x*x for x in range(5)). use () instead of []
  

**Q. Generator vs Iterator :**    
  - every generator is an iterator, but not every iterator is a generator. An iterator is a general concept for any object that allows sequential traversal of data by implementing the iterator protocol (__iter__ and __next__ methods), whereas a generator is a specific, subclassed type of iterator written as a function that uses the yield keyword to produce data lazily

### Dataclasses :
 provide a built-in decorator (@dataclass) that automatically generates special "dunder" methods—such as __init__(), __repr__(), and __eq__()—for classes primarily used to store data. This eliminates a massive amount of repetitive boilerplate code, making your data-rich objects cleaner, more readable, and easier to maintain.

```python
Traditionally :
 class Employee:
     def __init__(self, name, age):
         self.name = name
         self.age = age

using dataclass :
 from dataclasses import dataclass
 
 @dataclass
 class Employee:
     name: str
     age: int
```

**Core Features :**

* **Auto-generated Methods:** Generates __init__, __repr__, and __eq__ out of the box based on type hints.
* **Default Values:** Assign basic defaults using standard Python assignment syntax. ex -> age: int = 18
* **Immutability (Frozen):** Pass frozen=True into the decorator to make instances read-only and hashable.
  - ex : @dataclass(frozen=True)
  - user.name = "Alice", raises an error. Similar to immutable objects.
* **Sorting Capabilities:** Use order=True to auto-generate comparison methods like __lt__ and __gt__.
* **Built-in Serialization:** Built-in helper utilities allow easy casting to other formats



**Q. Why use Dataclasses?**  
- Less code.  
- Cleaner.  
- Better readability.  
- auto Generates __init__, __repr__, and __eq__   
- Perfect for:  
  - API models
  - Config objects
  - DTOs (Data Transfer Objects)

**Q. When would you use a normal class instead?**  
When the class contains significant business logic or custom initialization.

**Q. Dataclass vs Pydantic (Interview)**

### Type Hints :

Type hints are an optional feature introduced in Python 3.5 via PEP 484 
- that allow you to explicitly declare the expected data types of variables, function parameters, and return values.
- Because Python is dynamically typed, the runtime does not enforce these hints.
- Instead, they act as metadata for improving IDE autocomplete features, generating self-documenting code, and catching bugs early using static type checkers like mypy.


Basic Syntax :
```
def add(a: int, b: int) -> int:
    return a + b
```


**Important Types :**
If you are using Python 3.9 or newer, you no longer need to import List and Dict from typing. You can use the built-in lowercase types directly instead:

* **nums: list[int]**   - Tells Python this is a list containing only strings.
* **data: dict[str, int]**  - Tells Python this is a dictionary where the keys are strings and the values are integers
* **Generics :** A Generic is a tool that allows you to write reusable code (functions or classes) that can work with any data type, while still maintaining strict type safety. Instead of locking a function into just processing integers or just strings, you use a placeholder variable (often called T). When the code runs, that placeholder adapts to whatever type you pass into it
```python

# The [T] declares 'T' as a generic type variable
def get_first_element[T](items: list[T]) -> T:
    return items[0]

# T becomes 'int' here; returns an int
first_num = get_first_element([1, 2, 3])  

# T becomes 'str' here; returns a str
first_word = get_first_element(["apple", "banana"])  
```


**Q. Do type hints enforce types? Are type hints mandatory?**  
No. Python ignores them at runtime.
They're mainly for:
- IDEs
- mypy
- Linters
- Documentation

**Q. Do they improve performance?**  
No. They improve maintainability.

### Exception Handling

It allows your program to intercept and manage runtime errors instead of crashing abruptly.

**Control Blocks :**
* try: Wraps the dangerous code that might cause a runtime failure.
* except: Catches and processes specific errors raised inside the try block.
* else: Runs code only if the try block executes with zero exceptions.
* finally: Always runs at the very end, making it ideal for closing files or releasing databases
  - Ex : file.close(), db.close(), connection.close()

```python
try:
    file = open("data.txt", "r")
    content = file.read()
    value = 10 / int(content.strip())
except ValueError:
    print("File did not contain a valid integer.")
except ZeroDivisionError:
    print("Cannot divide by zero.")
else:
    print(f"Success! The result is {value}")
finally:
    file.close()
    print("File resource closed safely.")
```

> Catch specific exceptions like - except FileNotFoundError: instead of general - except Exception as e:  


* **Raise :**
**The raise keyword in Python forces an exception to occur immediately. It disrupts the normal line-by-line execution of your code and forces the program to either find a matching except block or crash with an error trace.**
You use raise followed by an exception class or an exception instance. If you pass just the class name, Python automatically initializes it behind the scenes
  
**When to Use raise :**    
- **Enforcing Business Logic and Constraints or custom exceptions : Use raise to stop execution when user inputs or data states break those rules.**
```
def process_withdrawal(balance, amount):
    if amount <= 0:
        raise ValueError("Withdrawal amount must be greater than zero.")
    if amount > balance:
        raise RuntimeError("Insufficient funds for this transaction.")
    return balance - amount
```

When you want to signal an error explicitly. It forces the program to either find a matching except block or crash with an error trace

No. Catch only those you can handle meaningfully.

### Reference Counting


**CPython :**  
CPython is the default, official reference implementation of the Python programming language. When you download Python from the official Python website, you are downloading and using CPython. It is called "CPython" because the core interpreter engine is written in the C programming language.  
CPython acts as both a compiler and an interpreter to translate your human-readable Python code into something your computer hardware can actually execute :  
1. Compilation to Bytecode: When you run a script, CPython first parses your source code (.py) and compiles it into an intermediate language called bytecode. This bytecode is saved in cached .pyc files.  
2. Interpretation via PVM: The Python Virtual Machine (PVM)—which is a stack-based software loop written in C—then reads the bytecode instructions line-by-line and translates them into native binary machine code for your specific operating system  



### Reference Counting  
**Every object in Python keeps track of how many variables are referring to it. This number is called the Reference Count.**    
```python
a = [1, 2, 3]
Memory : a ─────────► [1,2,3]
         Reference Count = 1

Now : b = a
Reference Count = 2
Two variables point to the same object

del a
Reference Count = 1
Object still exists.

del b
Reference Count becomes : 0
Python immediately frees the object.
```

> **When the reference count reaches zero, CPython immediately deallocates the object.**
> **This is Python's primary memory management mechanism.**

**Q: When is an object destroyed?**  
- When its reference count becomes 0.

**Q: Does del delete the object?**  
- No.
- It removes a reference.
- If other references exist, the object remains alive.

### Garbage Collection

**Why isn't reference counting enough?**    
**consider : **  
```python
class A:
    pass

a = A()
b = A()

a.ref = b
b.ref = a

Now:
 del a
 del b

Problem:
- The objects still reference each other.
- Reference count never reaches zero.
- Without another mechanism, they would never be freed.
```
> **This is called a circular reference**
**Solution: Garbage Collector (GC)**

- **Python has a cyclic garbage collector.**
- **It periodically searches for unreachable objects involved in circular references and frees them.**
- **Reference counting handles most objects immediately, while the garbage collector detects and cleans up circular references that reference counting alone cannot reclaim.**


**Q. Reference Counting vs Garbage Collection**
| Reference Counting  | Garbage Collection |
| ------------------- | ------------------ |
| Immediate           | Periodic           |
| Primary mechanism   | Backup mechanism   |
| Fast                | Slightly slower    |
| Can't handle cycles | Handles cycles     |

### Memory Management

**Where are objects stored?**
- **Variables (references) live in stack frames during function execution and only hold the memory address pointing to heap object**
- **Objects themselves are allocated on the heap.**

**The Core Division: Stack vs. Heap**    
Python splits its runtime memory into two primary regions :  
**1. The Private Heap:** This contains the actual data objects (e.g., integers, strings, lists, dictionaries, custom classes, and even functions).  
**2. The Call Stack:** This stores temporary function execution blocks and object references (pointers), rather than the data itself  

```python  
When you write x = [1, 2, 3],
the list object [1, 2, 3] is allocated inside the private heap.
The variable name x lives in the call stack and merely holds the memory address pointing to that heap object.
```

### Shallow vs Deep Copy  
The core difference is that a shallow copy only clones the outer container while sharing references to nested objects, whereas a deep copy recursively duplicates everything, creating a completely independent clone.  

**Shallow Copy:**    
A shallow copy builds a new compound object but populates it with references to the child objects found in the original.
```python

original = [[1, 2, 3], [4, 5, 6]]
shallow = copy.copy(original)

# Modifying the top-level structure doesn't affect the original
shallow.append([7, 8, 9]) 
print(original)  # Output: [[1, 2, 3], [4, 5, 6]]

# Modifying a nested mutable object DOES affect the original
shallow[0][0] = 'X'
print(original)  # Output: [['X', 2, 3], [4, 5, 6]]
```

**Deep Copy:**    
A deep copy recursively duplicates every object it encounters. It builds a brand new standalone graph of data.  
```python
import copy

original = [[1, 2, 3], [4, 5, 6]]
deep = copy.deepcopy(original)

# Modifying a nested mutable object has no side effects on the original
deep[0][0] = 'Z'
print(original)  # Output: [[1, 2, 3], [4, 5, 6]]
print(deep)      # Output: [['Z', 2, 3], [4, 5, 6]]
```


**Q1. Difference between assignment and shallow copy?**    
- Assignment copies the reference.
- Shallow copy creates a new outer object.
- The fundamental difference is that assignment (=) creates a new reference to the exact same object in memory, whereas a shallow copy creates a brand-new container object but fills it with references to the nested items of the original.
- **An assignment statement does not copy anything. It simply binds a new variable name to the existing object. A shallow copy constructs a new outer compound object. It then populates it with references to the items found in the original. Modifying the top-level container does not affect the original but Modifying a nested mutable object affects original as well. If you need the nested objects to be completely independent as well, you must use a Deep Copy.**   


**Q2. Difference between shallow and deep copy?**    
- Shallow copies only the first level.
- Deep copy recursively copies all nested objects.


**Q3. When do you use deep copy?**    
- When working with nested mutable objects that must be completely independent.

**Q4. Real Interview Example**    
```python

a = [[1], [2]]
b = copy.copy(a)
b[0].append(10)
print(a)

output : [[1,10],[2]] ---> Because the inner list is shared.
```

### Concurrency 
Concurrency in Python is the ability to manage and execute multiple tasks in overlapping time intervals. It is about dealing with a lot of things at once rather than doing them simultaneously (which is parallelism). In Python, concurrency is primarily used to prevent a program from wasting time while waiting for external operations to finish.
Most of the time, your program is waiting (I/O), not computing. Python provides different ways to use that waiting time efficiently.
There are three main concurrency models:
1. Multithreading
2. Multiprocessing
3. AsyncIO

#### Q. When should I use which?  

**Race Condition:**  
A race condition is a flaw in a system where the output depends on the uncontrollable timing or sequence of events, such as when two or more threads access shared data simultaneously. This leads to unexpected errors, data corruption, or security issues.

### GIL :  
**The Python Global Interpreter Lock (GIL) is a mutual-exclusion lock (mutex) used by the default CPython interpreter to ensure that only one thread executes Python bytecode at a time.** 
This means that even if your computer has a multi-core processor, a multi-threaded Python program will only run on a single core at any given

**Q. Why does Python have a GIL?**   
> Because CPython uses reference counting for memory management.
> So if two threads are trying to access an object simultaneously, it could lead to race condition. 
> The GIL helps protect Python's internal object management and simplifies memory handling. 


**Q. Does GIL allow only one thread?**    
- Yes—for Python bytecode. Even if we create 10 threads, only one executes Python code at a time in a single CPython process.

**Q. Then why use multithreading?**    
- Because while one thread is waiting (network, file, database), it releases the GIL. Another thread can run.
- This makes threads effective for I/O-bound work.

**Q. Does every Python implementation have a GIL?**  
- No. CPython has it.
- Implementations like Jython and IronPython do not use the same GIL model.

**Q. Does GIL affect multiprocessing?**  
- No. Each process has its own Python interpreter and its own GIL.

**Q. CPU-bound vs I/O-bound**   
**CPU-bound : The CPU is busy doing calculations. Needs more CPU**  
- Image processing
- Video encoding
- Machine learning
- Large loops
- Encryption

**I/O-bound: Program spends time waiting. Needs Less waiting**  
- Database
- REST API
- Reading files
- Network
- Redis

### Multithreading  

Multithreading in Python allows your program to run multiple flows of execution concurrently within a single process. It is highly efficient for I/O-bound tasks (like downloading files, web scraping, API calls, or reading data) where the program spends most of its time waiting for external resources. However, due to Python's Global Interpreter Lock (GIL), standard Python threads do not run in true parallel on multiple CPU cores, making them ineffective for CPU-bound tasks like heavy calculations
A thread is a lightweight unit of execution inside a process. All threads:
- Share memory
- Share variables
- Share resources

**Q. When to Use vs. Avoid Multithreading**  
When tasks spend most of their time waiting. For I/O-bound tasks, where threads spend most of their time waiting for external resources.
Because threads share the same memory space inside a single process, Python behaves differently depending on the workload
- 🟢 Use for I/O-Bound Tasks: Web scraping, database queries, API calls, or file read/write/download operations. When one thread blocks to wait for the network, Python pauses it and lets another thread take over.
- 🔴 Avoid for CPU-Bound Tasks: Matrix math, image/video processing, or machine learning training. The GIL allows only one thread to execute Python code at a time. For CPU-intensive operations, use the multiprocessing module instead to bypass the GIL

---

### Multiprocessing  

Python's multiprocessing module allows you to run multiple tasks in parallel by spawning separate operating system processes, each with its own Python interpreter and memory space. This completely side-steps the Global Interpreter Lock (GIL), enabling your code to fully utilize multiple CPU cores for heavy, computation-bound tasks. Suitable for Al, ML, Image/Data/Video processing.
Instead of threads, create multiple processes. Each process has it own memory and GIL, Now multiple CPU cores can work simultaneously.
- True parallelism
- Uses multiple CPU cores
- No GIL limitation between processes
- Higher memory usage
- Slower process creation
- Inter-process communication is more complex
- If you need precise control over individual, distinctly different tasks running in the background, use the Process class directly


----

**MultiThreading Vs Multiprocessing:**     

> **You (the developer) decide whether to use multithreading or multiprocessing by choosing which library to write into your Python code**


Multithreading creates multiple threads within a single process. Threads share the same memory, making communication fast and lightweight, but in CPython they're limited by the GIL, so only one thread executes Python bytecode at a time. As a result, multithreading is ideal for I/O-bound tasks such as API calls, database operations, and file handling.

Multiprocessing creates multiple independent processes, each with its own memory space and its own Python interpreter (and GIL). This enables true parallel execution across multiple CPU cores, making it the preferred choice for CPU-bound tasks like data processing, image processing, and machine learning computations, though it has higher memory usage and process creation overhead.


**When to write Multiprocessing:**  
- Your code is grinding your CPU to 100% capacity.
- Image processing, machine learning training, video rendering, heavy math, or sorting giant datasets.
- It creates entirely separate instances of Python to bypass the Global Interpreter Lock (GIL), forcing your operating system to distribute the work across multiple physical CPU cores.


**When to write Multithreading:**  
- Choose this when your script spends most of its time waiting for external actions to complete
-  Web scraping, downloading multiple files, calling APIs, or reading/writing large files.
-  While one thread is sleeping or waiting for a website to respond, Python instantly switches to another thread to keep working. It uses very little memory because all threads share the same space

| ------------- | --------------- |
| Shared memory | Separate memory |
| Lightweight   | Heavyweight     |
| GIL affected  | Not GIL limited |
| I/O-bound     | CPU-bound       |

**Q. How Multithreading Works in Languages Without a GIL**    
**In languages without a GIL—such as Java, C++, Rust, and Go—multithreading delivers true parallelism. But you have to manually create mutext locks, Semaphores, or Thread-Safe Data Structures**
When you create multiple threads on a multi-core CPU, the operating system maps those threads directly onto different physical hardware cores
- **The Mechanism:** Each core executes its assigned thread's instructions simultaneously. If you have 4 threads running a heavy math equation on a 4-core processor, all 4 cores spike to 100% usage, completing the job in roughly one-quarter of the time
- **The Shared Memory Problem:** Because these threads run at the exact same time and share the same memory space, they can access the same variables simultaneously. If Thread A reads a variable at the exact millisecond Thread B is overwriting it, the application will crash, corrupt data, or trigger unexpected bugs. This nightmare scenario is called a race condition
- **The Solution:** Developers writing in GIL-less languages must manually build safety boundaries. They use synchronization tools like Mutexes (Mutual Exclusion locks), Semaphores, or Thread-Safe Data Structures to safely gatekeep data. If a thread wants to change a variable, it must "lock" it, make the change, and "unlock" it so other threads can safely access it next


**Q. What Is the Use of the GIL?**    
Python's default interpreter (CPython) features a GIL to solve a major internal challenge: Memory Management.
Python uses a mechanism called Reference Counting to track objects. Every time you create an object or assign it to a new variable, Python increments an internal counter. When you delete a variable or it goes out of scope, the counter drops. Once that counter hits zero, Python safely wipes the object from memory (Garbage Collection).
Without a GIL, two threads could modify an object's reference counter at the exact same instant. This could trigger a race condition where the counter accidentally drops to zero while an object is still actively in use, destroying data and crashing your script.
To prevent this internal memory corruption, the creator of Python introduced the GIL. It acts as a single, all-encompassing lock: only one thread can hold the interpreter lock and execute Python code at any given moment.


Q. Why doesn't multithreading speed up CPU-bound tasks in CPython?
- Because the GIL allows only one thread to execute Python bytecode at a time.

Q. Can threads still run in parallel?
- Native code that releases the GIL (e.g., some NumPy operations or C extensions) can execute in parallel. The GIL mainly limits execution of Python bytecode.

Q. How do processes communicate if they don't share memory?
- Through inter-process communication (IPC) mechanisms such as multiprocessing.Queue, Pipe, shared memory, or a Manager.

Q. When would you choose threads over processes?
- When tasks spend most of their time waiting for I/O, because threads are lightweight and sharing memory makes coordination simpler.

Q. When would you choose processes over threads?
- For CPU-intensive workloads where you want to utilize multiple CPU cores and avoid the GIL's limitations.

### AsyncIO

**Asyncio is a built-in Python library used to write concurrent code using the async and await syntax. It is designed for I/O-bound operations (like web scraping, API calls, and database queries) rather than CPU-bound operations (like heavy mathematical computations). Unlike multithreading or multiprocessing, asyncio achieves concurrency on a single thread by using an event loop to pause and resume tasks during waiting periods.**

**Core Concepts:**
**Event Loop:** The engine that manages and distributes the execution of different tasks. It runs in the background and switches context when a task hits a waiting point.
**Coroutine:** A specialized Python function defined with async def. Calling it returns a coroutine object instead of executing the code immediately.
**Awaitable:** An object that can be used with the await expression. The most common awaitables are Coroutines and Tasks.
**Task:** A wrapper that schedules a coroutine to run concurrently on the event loop

> To run an asynchronous program, you must declare a coroutine using async def, yield control using await, and kick off the execution with > asyncio.run().

```python
import asyncio

async def fetch_data():
    print("Start fetching...")
    # Simulate a network delay (non-blocking)
    await asyncio.sleep(2) 
    print("Data fetched!")
    return {"data": 123}

async def main():
    # Run the coroutine and wait for the result
    result = await fetch_data()
    print(f"Result: {result}")

# Entry point to execute the main event loop
asyncio.run(main())
```

**Golden Rules of asyncio :**

**Do not use blocking code:** Avoid synchronous blocking functions like time.sleep() or requests.get(). They freeze the entire event loop. Use their async alternatives (e.g., asyncio.sleep(), aiohttp, or httpx).
**Keyword pairing:** The await keyword can only be used inside an async def function.
**Top-level execution:** Use asyncio.run() exactly once as the main entry point of your application. Avoid using it to wrap individual internal functions.



### Ayncio vs MultiThreading :
asyncio and multithreading are both techniques used to achieve concurrency in Python, but they operate on completely different mechanisms.The core difference is that asyncio uses a single thread and switches tasks voluntarily, while multithreading uses multiple OS threads and the operating system switches between them automatically


Q. Synchronous vs ASynchronous :  
Synchronous: Each task waits for the previous one to finish.  
Asynchronous: A task can pause while waiting, allowing other tasks to run.  

Q. What is Thread Safety?  
Code is thread-safe if multiple threads can execute it without producing incorrect results.  
Ex : counter += 1
- Two threads may execute this at the same time.
- Result can become incorrect due to a race condition.


Q. Race Condition
Two threads modify shared data simultaneously.   
Solution:  
Use a lock. Only one thread enters the critical section at a time.  

Best Practices:

- Use locks only when needed.
- Prefer thread-safe queues (queue.Queue) for communication.

### Context Managers (with)
context manager in Python is an object that handles the automatic allocation and release of resources.It is most commonly invoked using the with statement, which ensures that cleanup code runs even if an error occurs within the block. This prevents resource leaks like unclosed files, locked databases, or dangling network connections

Instead of manually opening and closing resources using a try...finally block, you use with. The built-in open() function acts as a native context manager
```python
with open("example.txt", "w") as file:
    file.write("Hello, World!")
# The file is automatically closed here, even if an exception occurs above.
```


Common Use Cases:
File Operations: Safely writing and reading data without dangling file descriptors.
Database Connections: Automatically committing changes or rolling back transactions on failure.
Thread Locks: Acquiring a lock when entering code blocks and releasing it automatically.
Performance Timers: Measuring the execution time of specific code blocks on exit



How with works :
```python
Conceptually:
 with resource as x:
     do_something()

is roughly:

x = resource.__enter__()
try:
    do_something()
finally:
    resource.__exit__(...)

--> That's the important mental model.
```

Custom Context Manager:
You can create your own context manager. __enter__ and __exit__
```python
class MyContext:
    def __enter__(self):
        print("Entering")
        return self

    def __exit__(self, exc_type, exc_value, traceback):
        print("Exiting")

Usage:
with MyContext():
    print("Inside")

Output:
Entering
Inside
Exiting
```

Why __exit__ is important
Notice def __exit__(self, exc_type, exc_value, traceback): 
It receives information about an exception if one occurred.
If exception occurs:
They contain information about the exception.
This allows the context manager to:
- clean up resources
- log errors
- optionally suppress exceptions


Exception Suppression:

If __exit__() returns: True
the exception is suppressed.
Then: The exception doesn't propagate.

If __exit__() returns False or None, the exception propagates normally.

### Contextlib 
contextlib is a built-in Python module that provides utilities for creating, modifying, and managing context managers.
It simplifies resource management by allowing you to build context managers without writing verbose classes with __enter__ and __exit__ methods
```python

@contextmanager
def database_connection():
    connection = connect()

    try:
        yield connection
    finally:
        connection.close()

Usage:
with database_connection() as conn:
    conn.execute(...)
```

Think of yield as the boundary
Everything before yield → setup.
Everything after yield → cleanup.

### File Handling

File handling in Python allows you to create, read, update, and delete files permanently on your storage system.
The best practice is to always use the with statement (context manager) when opening a file. This automatically closes the file once the code block finishes executing, preventing memory leaks and file corruption

Opening a File:

```python
f = open("data.txt", "r")
Ex : open("file.txt", "r")
     open("file.txt", "w")
```

```python
with open("large.txt") as f:
```

```python
with open("data.txt", "r", encoding="utf-8") as f:
```

Different systems can use different default encodings.  
Explicit encoding avoids inconsistent behavior.
